FINDING (changed the engine): with conn.query / stmt.query the slow statement BLOCKED the duckdb-wasm worker:
  cancelSent, close and every later query queued behind it and the test hung to its 120 s timeout. The engine now
  runs statements with stmt.send() (a pending, polled query) and reads the batches; cancelSent then interrupts it.
  So the design's "Promise.race plus cancelSent()" works only with send(), not query().

Departures (owner please read)
  - rows_dropped is exact: COUNT(*) OVER () AS total_groups instead of LIMIT n+1 (spec asked to record this).
  - Result carries status:'ok', aggregate and group_by besides the AI-09 fields (status discriminates the three
    outcomes; aggregate.col feeds queryResultToCheckerCard's metric "<view>.<col>").
  - n is COUNT(<measure>) (non-null rows behind the value) for avg/median/min/max/sum, COUNT(*) for count.
  - A count request names the view's count_name (laps, stints, stops, races, ...) as col.
  - LIMIT is a validated integer (1..25) interpolated, not bound; everything else is bound.
  - Season filters: eq / in / between only, at most 2 seasons on any view (1 on qv_teammate_corners), each in
    catalogue.seasons; season integers for aliases are taken from the catalogue list. Race-partitioned aliases
    carry sha256(race_id)[:12], never the request string; file URLs come from manifest paths only.
  - One filter per column; unknown request keys (including __proto__ from JSON.parse) are bad_value.
  - Default filter is_major_outlier_lap = false on qv_laps unless the request filters that column (and a note).
  - Not wired into the app: nothing imports realEngine.ts yet (AX-10 does). The DEV-only window hook is behind
    import.meta.env.DEV; a production build was not run to prove it is stripped (the module is not in the
    bundle at all today).
  - AX-14 grounding store: store.ts keeps the last 200 results per session.
