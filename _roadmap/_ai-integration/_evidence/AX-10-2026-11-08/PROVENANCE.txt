OWNER DECISIONS / FINDINGS
  1. teammate_id: NOT added to tools.template.json (keeps the Worker tools and token count unchanged). The card store derives the teammate for
     resolveBundle's teammateOf: from the race.teammate_gap card display ("... vs PER ..."), else the one other driver of the same constructor in
     race.result; null if none or ambiguous (then the teammate steps are reported in missing_scope). Fragile if the display format changes;
     a policy_fields.teammate_id on the gap card (AX-07 / mart column teammate_id already exists) would be sturdier. Owner: accept or add the field.
  2. make_chart / compare_lap_times registered for real (AX-11 landed), not as stubs. make_chart's schema is {result_id, kind}; the dispatcher builds
     the chart spec from the stored result (group_by[0] on x, value on y). Row-cap check repeated: no row_cap/rowCap/maxRows string in the generated
     tools.ts or tools.template.json; query_data limit max 25; compare_lap_times schema = race_id, driver_a, driver_b only; a rowCap key sent to
     any tool is refused by the strict top-level key check before the tool runs (tested for three spellings).
  3. The Worker's ticket allows 5 model rounds; the repair turn is a model round and shares them. A question that spends all 5 (4 tool calls + answer)
     cannot be repaired: it returns the draft with notes REPAIR_SKIPPED. Option: AX-12 grants a 6th round for repair only.
  4. worker/src/generated/tools.ts is generated from an OLDER card index (10 kinds): get_fact_cards kinds enum lacks the AX-07b / AX-15a kinds
     (e.g. dirty_air.price), so a real model could not ask for them by kind. The CLI regenerates in memory from the registry. Owner: re-run
     `cd worker && npm run gen-tools` after `make app-data` (AX-08 step 1) before any Worker deploy.
  5. Grounding rules (grounding.ts header): sources = card value, interval ends and level (level grounds "95%" only), n, display and reason
     texts; every number in query_data / compare / chart results; numbers in the question. Not checked: years 1950-2099, ids, citations, list
     markers, numbers glued to letters. Whole numbers match exactly (or round a source >= 10). display is accepted although the model projection
     does not carry it (render-time use by AX-14 needs it); a stricter model-visible-only mode is a one-line change if wanted.
  6. The checker is run on EVERY card the model received this question, not only the cited ones (a held stub it ignored still demands HELD wording).
     Conservative; AX-13 should measure how often that costs a repair turn.
  7. Finding for AX-21/AX-13: the teammate_race bundle includes driver_race.pit_stops, whose source (int_pit_strategy_value) fires
     PIT_CALL_REPRODUCTION_RATE, and the held race_driver.skill_components stub fires HELD_CARD_WORDING + ONE_SKILL_MEASURE; a compliant
     teammate_race answer must carry the pit-call-reproduction sentence, the held wording and the "different measures" sentence. system.md has
     the first two ideas; the third is only in the glossary. A real model may need the repair turn on most teammate_race questions: measure in AX-13.
  8. Cloudflare facts: function calling listed as supported (fetched 2026-11-07). Multi-round tool use and reasoning-token accounting UNVERIFIED;
     nothing here claims them. All token figures are chars/4 estimates of a SCRIPTED model; AX-13 measures the real ones.
  9. History replays only (question, final answer) of the last two turns; tool results are never replayed.
