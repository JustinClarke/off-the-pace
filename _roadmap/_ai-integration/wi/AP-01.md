## The problem (re-verified 2026-11-07)

- `lap-waterfall/queries.ts:48-56` (single race) and `:74-82` (season) wrap every component in `COALESCE(AVG(x), 0)`. `pace_delta_s` is rebuilt as `COALESCE(AVG(total_explained_s), 0) + COALESCE(AVG(driver_skill_residual_s), 0)`.
- `race-lost/queries.ts:45-53` does the same with `SUM`.
- The transforms then treat every value as a number: `lap-waterfall/transform.ts:32` and `race-lost/transform.ts:26` (`row[key] as number`). The CSV writes `.toFixed(4)` (`race-lost/transform.ts:54`).

**The log note is only partly right. What the COALESCE actually hides** was measured on the scratch warehouse, on the population these queries read (`NOT is_major_outlier_lap AND fuel_component_s IS NOT NULL`, 160,895 laps):

| Column | NULL laps | Driver-race groups where every lap is NULL (so the page shows 0) |
|---|---:|---:|
| `driver_skill_residual_s` | 12,300 | **102** (e.g. 2018_1 RIC, VET, VAN) |
| `track_unexplained_s` | 11,471 | (same races) |
| `total_explained_s` | 2,474 | |
| `compound_component_s` | 2,443 | **54** |
| `dirty_air_tax_s` | **31** | |
| `constructor_component_s` | 0 | |

So for **dirty air** the COALESCE almost never fires. The 0 s comes from the transform layer, which writes 0.0 on unmeasured laps: 11,471 laps in this population have `pace_delta_s IS NULL` and `dirty_air_tax_s = 0`. TX-03 fixes only the aggregates; the lap column stays 0.0 (moving it is TX-03's separate owner decision, option B), so this page must tell measured from unmeasured itself. For **skill, compound and track noise**, this page bug alone turns "no data" into "0 s". AVG over a partly NULL column also silently averages fewer laps than `n_laps` reports.

## Method

1. **Queries** (both files). Drop every `COALESCE(..., 0)`. For each component add `COUNT(x) AS n_<component>` beside `COUNT(*) AS n_laps`. Return `pace_delta_s` / `total_pace_delta_s` as NULL when either part is NULL. **Dirty air:** there is no measured flag to read. A lap's dirty air is unmeasured exactly when `fct_lap_residuals.pace_delta_s IS NULL` (TX-03's `assert_dirty_air_fill_only_where_base_unmeasured` makes that a tested invariant). So average `CASE WHEN pace_delta_s IS NOT NULL THEN dirty_air_tax_s END`, count `COUNT(pace_delta_s) AS n_dirty_air_tax_s`, and return NULL when the count is 0. If TX-03's test has not landed, still use this rule and say so in the hand-back.
2. **Types.** Component fields in `LapResidualRow` and `RaceLostRow` become `number | null`, and the `n_*` counts are added.
3. **Transforms.** A NULL component becomes a bar marked `unavailable` (add `unavailable?: boolean` to `WaterfallBar` in `ui/charts/Waterfall.tsx`). It has no height, adds nothing to the running sum, and its tooltip and label read "unavailable" with the reason ("no measured laps"). `closureGap` is NULL when any identity term is NULL. The CSV writes an empty cell, not `0.0000`.
4. **Partial coverage.** Where `n_<component> < n_laps`, show "based on k of n laps" for that bar.
5. Do not change which laps are selected (the `WHERE` clauses), the colours, or the identity order.

## Acceptance

- In the real app (`pnpm dev` in `app/`), 2018 round 1 shows "unavailable" for Driver Skill and Track noise for RIC, not 0.000 s. Dirty Air also shows "unavailable" there (the `pace_delta_s` rule).
- A race with full data renders bars identical to today (same values to 4 dp).
- The CSV from that 2018 race has empty cells, not zeros.

## Tests to add (vitest, the existing `transform.test.ts` in each feature)

- A NULL component yields an `unavailable` bar with value NULL, and the next bar's `start` ignores it.
- `closureGap` is NULL when a term is NULL, and unchanged when none is.
- The CSV row for a NULL component is empty.
- `n_<component> < n_laps` sets the partial-coverage label.

Run in `app/`: `pnpm exec vitest run src/features/lap-waterfall src/features/race-lost`, then `pnpm typecheck` and `pnpm lint`.

## Definition of done

Both pages show "unavailable" instead of 0 for missing components, the tests above pass, typecheck and lint are clean, and a full-data race is unchanged. Do not commit.
