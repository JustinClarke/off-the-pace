## The problem (re-verified 2026-11-07)

- **The simulator.** `degradation-simulator/page.tsx:273-275` hard-codes `modelVersion: '3'` and `datasetFingerprint: 'b8a37b7c'`, and puts `'ONNX parity 7.6e-6 (max abs) vs trained boosters'` in the `dataWindow` slot. The shipped `app/public/models/manifest.json` says `model_version: "v14"`, `dataset_fingerprint: "5dbd8e51502a…"` (line 444). The footer therefore prints `v3 · sha:b8a37b7c` for v14 models.
- **The data window.** 27 provenance props hard-code `dataWindow: '2018–2025'` or `'2018-2025'` (two dash spellings). One more falls back to `'2018-2025'` when `profile?.data_window` is missing.
- **No page shows which data build it read.** The data manifest has `version` (`30f91247d7cb651e`), `generatedAt` and `stats.seasons` (`"2018–2025"`). `ProvenanceMeta` has no field for the data version.
- `model-metrics/page.tsx:63-64` already reads version and fingerprint from data, so it is the pattern to copy.

## Method

1. **One hook.** Add `useProvenance(opts)` (for example in `app/src/data/provenance.ts`). It loads `loadManifest()` once and, when `opts.models` is set, `loadModelManifest()`. It returns:
   - `dataWindow`, from `stats.seasons`;
   - `dataVersion`, from manifest `version`;
   - `generatedAt`;
   - `modelVersion` and `datasetFingerprint`, from the model manifest.

   Extend `ProvenanceMeta` with an optional `dataVersion` and render it in both `Provenance.tsx` and the `FeaturePage` footer (`data:<first 8>`).
2. **Replace the literals.** Every `dataWindow: '2018–2025'` / `'2018-2025'` becomes the hook value. Keep page-specific windows that are computed already (`eraLabel`, `trainedOn`, `training_seasons`, `profile?.data_window`), but replace their `'2018-2025'` fallback with the hook value. List every file changed.
3. **The simulator.** Take `modelVersion` and `datasetFingerprint` from the model manifest. Move the ONNX parity text out of `dataWindow` into the methodology content or a labelled note.
4. **After TX-05 and TX-11:** also show the label version (for example `label v16`) when the data manifest carries it. Until then the field is absent and nothing renders, so there is no placeholder text.
5. If a manifest fails to load, the provenance footer omits the field. It never shows a literal.

**Must not move:** no data query, no rendered number other than the provenance line, no change to the manifest files themselves.

## Acceptance

- `grep -rn "dataWindow: '2018" app/src` returns nothing. `grep -rn "b8a37b7c\|modelVersion: '3'" app/src` returns nothing.
- In the real app (`pnpm dev`), the simulator footer shows `v14 · sha:5dbd8e51`, and a sample of three other pages shows `2018–2025 · data:30f91247`.
- With the model manifest request blocked, the simulator footer shows no version and no stale literal.
