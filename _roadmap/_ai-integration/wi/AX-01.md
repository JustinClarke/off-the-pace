## Decided (design 2.2, AD3, AD5)

- One row per card, stored as the `assistant_cards` table (one parquet partition per season, plus one `_global`). Deterministic id: `kind:scopekey:variant`, for example `race_lost.component:2024_8:LEC:compound`.
- Labels: `measured | modelled | computed | experimental | unavailable`. `unavailable` is a value with a reason, never 0.
- `n` is required on every card, as `{count, unit}`. A source row with no `n` becomes no card and goes on the ungrounded list.
- `modelled` and `experimental` require an interval. `interval.kind` is one of `ci_bayes | ci_bootstrap | ci_normal_95 | ci_order_stat_median | lap_noise_band | pred_band_p10_p90 | se_1 | none`, copied from the registry entry, never inferred. `ci_normal_95` is estimate ± 1.96 × SE (the era rating, AX-04 finding 7); `ci_order_stat_median` is the distribution-free CI for a median (the race rating after TX-01).
- `status` is `active | held | withdrawn`. A `held` card is published (so the assistant can say why a number is not there yet) and has no `value`.
- The chance line has no card kind (AD5). Enforced in the registry (AX-04), not here.

## Findings that change the method

1. **The existing rules read flat fields, the new card nests them.** Triggers in `policy.json` read `n` (a number, `THIN_SAMPLE`: `n_unit eq "stints"` and `n lt 8`), `n_unit`, `source_page`, `source_table`, `model_version`, `sample`, `grade`, `trust_label`, `calibration_flag`, `car_term_source`, `is_in_envelope`, `beats_baseline_significant`, `caveats`, `scope.season` and `metric`. The design nests `n.count`, `n.unit`, `versions.model_version`, `page.docs_slug` and `source.mart`. If `checker.ts` is simply switched to the new type, 13 `caveats` triggers still work but `THIN_SAMPLE`, `IN_SAMPLE_FIT` (`source_page`) and others silently stop firing. So the checker keeps its loose `FactCard`, and a pure function `toCheckerCard(card)` flattens a card into it (below).
2. **No schema validator is in `app/package.json`** (no ajv or zod). Use `ajv` as a devDependency (the owner will see a `package.json` and `pnpm-lock.yaml` diff) or hand-write the validator from the schema. Decide and record which in the doc's run note.
3. The design says `interval` may be null only for `measured | computed`. `unavailable` and `held` cards also need a null interval. This item allows null for those too.
4. The design says cards without `n` are refused, but an unavailable or held card has no sample. Rule used here: `n.count` is an integer >= 0 on every card, `0` for held and unavailable cards.

## Method

1. Write `app/src/assistant/cards/card.schema.json` (JSON Schema 2020-12) with every field of design 2.2: `id, kind, metric, label, value, unit, display, unavailable_reason, n{count,unit}, interval{low,high,level,kind,source_columns}, scope{season,race_id,driver_id,constructor_id,circuit_id,compound,stint_id,lap}, source{mart,columns,feature,query,transform}, versions{data_version,label_version,model_version,card_schema,registry}, page{route,params,docs_slug}, caveats[], sample, grade, status, held_reason`. Add one extra field, `policy_fields` (object), for registry-supplied flags the policy reads (`trust_label`, `car_term_source`, `calibration_flag`, `is_in_envelope`, `beats_baseline_significant`).
2. Constrain with `if/then`: `label=unavailable` requires `value=null` and `unavailable_reason`; `status=held` requires `value=null` and `held_reason`; `label in {modelled, experimental}` requires a non-null interval with `kind != none`; `n.unit` is an enum (`laps, stints, races, drivers, cells, rows`) because `THIN_SAMPLE` matches the literal `stints`; `value` null only when `unavailable` or `held`.
3. Generate `app/src/assistant/cards/card.types.ts` and a Python `TypedDict` file (`scripts/assistant_cards/card_types.py`) from the schema with one script, `app/scripts/gen-card-types.mjs`. Check generated files in; a test fails if they are stale.
4. `app/src/assistant/cards/validate.ts`: `validateCard(card, opts?: {expectedIntervalKind?: string})` returns `{ok, errors[]}`. When `expectedIntervalKind` is given (the registry's value, passed by AX-04), a different `interval.kind` is an error. That is the "relabelled interval kind" check.
5. `app/src/assistant/cards/project.ts`:
   - `toModelProjection(card)`: compact keys `{id, m, v, u, lbl, n:"51 laps", iv:[low,high,kind]|null, cav, pg}` plus `why` (the unavailable or held reason) only when `v` is null. About 45-60 tokens per card (design 2.2).
   - `toCheckerCard(card)`: `n = n.count`, `n_unit = n.unit`, `source_page = page.docs_slug`, `source_table = source.mart`, `model_version = versions.model_version`, `...policy_fields`, and pass through `id, kind, metric, label, status, value, unit, scope, caveats, sample, grade, interval`. `label` and `status` are needed by the AX-09 rules (unavailable, held, computed_not_card).
6. Document the parquet column layout of `assistant_cards` in the schema file's `$comment`: scalar columns for `id, kind, metric, label, value, unit, display, unavailable_reason, n_count, n_unit, interval_low/high/level/kind, sample, grade, status, held_reason, season`, and JSON-string columns for `interval_source_columns, scope, source, versions, page, caveats, policy_fields`.
7. In `checker.ts` change only the doc comment (line 13-14: "until AI-01 lands" becomes a pointer to `cards/card.types.ts`) and add `export type { Card }`. Do not change `FactCard`, the triggers or `policy.json`.

## Acceptance

- `validateCard` accepts 10 fixture cards and rejects 10 bad ones. The bad ones: no `n`; `modelled` with no interval; `experimental` with `kind: none`; `unavailable` with a value; `held` with a value; `unavailable` with no reason; `n.unit` outside the enum; `label` outside the vocabulary; `interval.kind` different from `expectedIntervalKind`; `low > high`.
- `npx vitest run src/assistant/honesty` passes with no edits to `checker.test.ts`, `sources.node.test.ts` or `policy.json`.
- `toCheckerCard` fixture test: a card with `n={count:5,unit:"stints"}` fires `THIN_SAMPLE`; a card with `page.docs_slug="blind-test-scoreboard"` and `sample="in_sample"` fires `IN_SAMPLE_FIT`.
- Projection of each valid fixture is at most 70 tokens by `estimateTokens`, and a projection never contains `route`, `params`, `source_columns` or `versions`.
