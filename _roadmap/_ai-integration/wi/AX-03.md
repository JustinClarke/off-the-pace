## Decided

- Cards link to pages through `page: {route, params, docs_slug}` (AX-01). A link must select the same race and driver the card describes.
- `navigate` stays a read-only tool that only accepts a shipped route and validated parameters. No model-written URL ever reaches the router (rule 6).

## Findings that change the method

1. **A deep link is wiped on arrival (read, not run; confirm in the e2e).** On the 12 pages that read `race` or `race_id`, a `useEffect` keyed on `[season]` deletes that parameter and runs on first mount (for example `race-lost/page.tsx:19-23`, `pit-strategy/page.tsx:56`). `?race=2024_8` would be stripped as the page opens. Fix: skip the clear on the first render (a ref flag), or clear only when `season` actually changes.
2. **`FilterContext` turns `race=2024_8` into `NaN`** (`Number(searchParams.get('race'))`, line 26). Only the waterfall uses it. Make the context ignore non-numeric `race` values instead of producing NaN.
3. **The existing test enshrines a link that selects nothing.** `assistantTools.test.ts:58-63` expects `navigate('/tyre-strategy/pit-gantt', {season:2024, race:7})` to give `?season=2024&race=7`, but the pit page reads `race_id` and a string. Update it.
4. The race-lost and waterfall pages keep the driver in local state, so no link can select one. Initialise it from a `driver` URL key (three-letter code).

## Method

1. New `app/src/nav/routeParams.ts`: `routeParams: Record<ShippedPath, Record<string, ParamSpec>>` where the key is the exact URL key above and `ParamSpec` is `{kind:'season'|'race'|'driver'|'constructor'|'circuit'|'compound'|'enum'|'int', pattern?, values?, encode?}`. Patterns: race `^\d{4}_\d{1,2}$`, driver `^[A-Z]{3}$`, season integer 2018-2025 (read the upper bound from the manifest `stats.seasons_list` if loaded, else `LATEST_SEASON` in `data/constants.ts`). The waterfall's `race` has `encode: 'round_int'` (`2024_8` becomes `8`, with `season=2024` also set). Add `driver` to race-lost and the waterfall.
2. `navigate(route, params?)` (v2): accepts string or number values, validates each key against `routeParams[route]`, rejects unknown keys and bad patterns with a structured error that lists the allowed keys, and builds the query with `URLSearchParams`. Keep the old `ALLOWED_FILTERS` export only if something imports it (nothing outside `nav/` does, per audit 4.2); otherwise remove.
3. `cardLink(card)` in `routeParams.ts`: maps a card's `page.params` to a validated URL. It never falls back to a guess; an invalid link returns `null` and the drawer shows no link.
4. Page edits (small): remove the mount-time clear (finding 1) on the 12 pages; seed `driverId` from the `driver` key on race-lost and the waterfall; harden `FilterContext` (finding 2).
5. Update `assistantTools.test.ts` for the new behaviour; do not weaken the route-list checks.

## Acceptance

- Static test: every path in `shippedPaths` has an entry in `routeParams` (possibly empty), and for each entry the key names appear in that route's page source as `searchParams.get('<key>')` or through `useFilters`. The test maps routes to page files by reading `App.tsx` `path:` / `import('./features/...')` pairs.
- `navigate` rejects an unknown key, a malformed race (`2024-8`), a driver in lower case, and any `sql` or `url` key.
- E2E (Playwright, `app/e2e/card-links.e2e.ts`): five card links land on their page with the race and driver selected: race-lost, waterfall, pit-gantt (`race_id`), degradation, survival (`race_id`+`compound`). Needs the local data (see AX-02 notes) and `VITE_DATA_BASE=""`.
- The 12-page clear fix: loading `?season=2024&race=2024_8` keeps `race` after mount.
