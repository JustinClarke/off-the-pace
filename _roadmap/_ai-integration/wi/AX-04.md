# AX-04 — Card registry and headless runner

**Group:** 3 foundations · **Depends on:** `AX-01` · **Model / cost:** `opus-5`, 2-3d
**Blocker:** none. `HD1` ruled A on 2026-11-07 (foundations start now; transform-class cards only; PK1 stands for ML and the held classes); `HD3` ruled A on 2026-11-07: cards are precomputed at publish time with each feature's own code run headless, then frozen and checksummed. This doc is written for A.

**Sources (checked 2026-11-07):**
- Query layer: `app/src/data/hooks/useQuery.ts` (the `queryRegistry` Map is module-private, line 7), `app/src/data/duckdb/client.ts`, `register.ts`, `app/src/data/manifest.ts`.
- Features: `app/src/features/race-lost/{queries,transform}.ts`, `era-ratings-timeline/{queries,transform}.ts`, `pit-strategy/{queries,transform}.ts`.
- `scripts/export_app_data.py`, `app/package.json`, `app/vitest.config.ts`.
- Design 2.3, 2.4, P2 and the 2.4 kind table; audit-app.md item 8; `wi/AI-01-grounding-contract.md` (v1, still valid for the refusal rules).
- Design says `app/scripts/build-cards.ts`. That path does not exist and a `.ts` entry cannot run (finding 2); use `build-cards.mjs`.

## Decided

- Cards come from the page's own `queries.ts` plus `transform.ts` (P2), so a card cannot drift from its page. A kind with no page uses an SQL kind over published files.
- `interval.kind` and `n` come from the registry entry, never from the data. A source with no `n` becomes no card and goes on the ungrounded list. The registry rejects any kind whose source is `flag_chance_lookup.json` (AD5; watch AXW6 clears with AX-17's guard test).
- Class T / T* / WC / ML is assigned by dbt lineage in AX-07, not here. This item gives the registry a `class` field and refuses to publish a class that is not in `classes_live`.

## Findings that change the method

1. **Nothing on disk to run against.** `app/public/data/` holds `_manifest.json` plus five parquet files (`marts/`, `ml/`); the 39 tables the manifest lists are not there. Headless runs need a scratch export through TX-12's `--db` / `--out` flags (do not add your own) from a scratch copy named `dev.duckdb`.
2. **Node cannot import the features directly.** They use extensionless relative imports (`race-lost/queries.ts:8-10`) that Node's TypeScript stripping does not resolve, and neither `tsx` nor `vite-node` is installed. `vite` is. Use `createServer({server:{middlewareMode:true}, appType:'custom', resolve:{alias}})` and `server.ssrLoadModule(...)`. Not tried.
3. **Three browser-only seams** must be swapped by alias: `data/duckdb/client.ts` (Worker plus wasm), `data/duckdb/register.ts` (`new URL(url, window.location.origin)` at lines 23 and 77) and `data/manifest.ts` (`fetch` of a CDN URL, line 42). The adapter provides `query()`, `getDb/getConnection`, `registerParquet(name, url)` (maps the URL back to a local path, ignoring `?v=`) and `loadManifest()` reading the local file.
4. **Engine choice (design: "not tried").** `@duckdb/duckdb-wasm` already ships Node bundles (`dist/duckdb-node-blocking.cjs`, `duckdb-node.cjs`); `@duckdb/node-api` is not installed. Spike the wasm Node bundle first (no new dependency). If it cannot read local parquet, add `@duckdb/node-api` as a devDependency and tell the owner.
5. **Calling a query by name** needs one export: add `getRegisteredQuery(name)` to `useQuery.ts`.
6. **race-lost has no interval to map.** `queryRaceLost` selects only sums and `n_laps` (`queries.ts:44-54`). The design's example card `race_lost.component` with a `lap_noise_band` and `ci_low/ci_high` is not supported by that query, so such a card would be refused (modelled needs an interval). The registry must say so with a reason; AX-07 and AX-15a/AX-15b decide whether an interval source exists (in v1 it is a held stub, AX-15a). race-lost is also T* (`dirty_air_tax_s` is inside `total_explained_s`).
7. **era rating interval kind.** `era_adjusted_rating_ci_low_s/high_s` is the rating minus/plus 1.96 times a standard error (`transform/models/intermediate/int_era_normalized_driver_rating.sql:179-181`). None of the design's kinds names a normal-approximation 95% interval. AX-01's enum now has `ci_normal_95` for this; use it (never relabel it as `ci_bayes`).

## Method

1. `app/src/assistant/cards/registry.ts`: `CardKindSpec` per design 2.4 `{kind, class, metric, label, intervalKind, nUnit, enumerate(index), build(params, q), pageParams(params), caveatRules, onScreen(params)}` plus `refusal(row)` returning a reason string. Export `registry`, `registryHash` (sha256 of the serialised specs, goes in `versions.registry`) and `classesLive` (initially `[]`).
2. Per feature, a `cards.ts` next to `queries.ts`. This item writes three: `race-lost/cards.ts` (kind registered but every row refused, finding 6), `era-ratings-timeline/cards.ts` (`era_rating.season`: value `era_adjusted_rating`, interval `ci_low/high`, `n = n_races` in `races`), `pit-strategy/cards.ts` (kind registered, status `held`, reason from PIT_CALL_REPRODUCTION_RATE until AX-18). Do not touch `page.tsx`.
3. `app/src/assistant/cards/headless/adapter.ts` implementing finding 3, and `app/scripts/build-cards.mjs` (Vite SSR loader, aliases, scratch data dir argument, writes nothing to `app/public/data` unless `--out` says so).
4. `buildCards(kindFilter?)` loops `enumerate`, calls `build`, runs `validateCard(card, {expectedIntervalKind})`, collects refusals into the ungrounded list with the reason.
5. Registry guard: a test fails if any spec's `source.mart` or query reads `flag_chance_lookup.json`, or if a kind's class is not in `classesLive` and it is not marked `held`.

## Acceptance

- `race-lost`, `era-ratings-timeline` and `pit-strategy` queries plus transforms run headless on a scratch export and return the same rows as the browser would.
- For 3 fixed parameter sets each, the card value (or the transform output the card is built from) equals (a) the transform output of the page's own call chain, and (b) an independent SQL oracle over the same parquet, at the page's display precision (state that precision per field in the test). Where Playwright's browser is installed, also read the rendered value for one set per feature; otherwise record that this was not done.
- `buildCards` never emits a card that `validateCard` rejects, and every refused row appears in the ungrounded list with a reason.

## Tests to add
