## Decided

- Views are narrow exported parquet tables written under `app/public/data/assistant/`, so the builder never joins and every column has a contract test. Lap-grain views are partitioned by `race_year`, like their sources.
- Request shape, aggregates, limits and result shape are fixed (design 2.5, AI-09). AX-06 implements them; this item publishes the vocabulary they validate against.
- Not in the catalogue: `int_corner_metrics`, `int_lap_air_state` (exposure semantics change under wake calibration), raw telemetry, raw flag tables, every modelled column.

## Findings that change the method

1. **"Built from published files" needs a second stage.** `export_app_data.py` reads the warehouse (`duckdb.connect(DB_PATH)`, `_run_export_to`). Rule 5 says views come from `app/public/data`. So build each `qv_*` in an in-memory DuckDB with `read_parquet` over the files the same run just exported (add the stage after the last export in `_run_export_to`, before the manifest). That makes a view provably a subset of published data.
2. **`schema.yml` is incomplete; build from the parquet.** `fct_lap_residuals` lacks `is_major_outlier_lap` in schema.yml but selects it (`fct_lap_residuals.sql:106`); `int_pit_strategy_value` lists no `race_id` or `driver_id` though `pit-strategy/queries.ts` filters on `pv.race_id`; `fct_ghost_race_finish` lists no `race_year, race_id, ego_driver_id, host_constructor_id` though the SQL selects them. Document each `qv` column from the exported parquet's own schema, never from `schema.yml`.
3. **Ghost actuals are partial.** `fct_ghost_race_finish` is "filtered to `recombination_confidence >= 0.3`" (schema.yml:1031), so `is_self_scenario` actuals may be missing for some driver-races. `qv_driver_race.actual_*` columns can be NULL; state it in the view note and never fill with 0.
4. **Telemetry delta columns are now verified**: `race_id, driver_a, driver_b, corner_name, track_id, lap_number, braking_point_delta_m, v_min_delta_kph, throttle_point_delta_m` (schema.yml). Only `race_id` can derive the season (`SPLIT_PART`, as `export_telemetry_deltas` does).
5. **Determinism.** `_content_hash` (line 211) hashes only file names and sizes, so two different values of equal size give the same manifest version. For the "stable on re-run" test, add an explicit `ORDER BY` to every view and compare the sha256 of each `qv` file across two runs. The version-hash weakness is fixed in AX-08.
6. Deny-list: the design lists `*hazard*_shrunk`. The unshrunk `sc_hazard_per_lap` and friends are still season-lagged model output (NULL for all 2018 rows). Deny any column containing `hazard`; keep only the count columns `prior_sc_onsets, prior_vsc_onsets, prior_racing_laps, prior_races_n`. Tell the owner this tightens the design.
7. **The CDN sync skips the new folder.** `scripts/publish_cdn.sh:90` syncs only `dimensions facts intermediates marts`. Files under `assistant/` will not upload until AX-08 step 4 adds it. Local development is unaffected (`VITE_DATA_BASE=""`).

## Method

1. Put view definitions in one Python module, `scripts/assistant_query_views.py`: per view `name, grain, note, partition_key, sql (over read_parquet), columns[{name, role: dimension|measure, type, ops, aggregates, description}], required_filters, max_seasons`. Views: `qv_laps` (driver x lap, joins `fct_lap_residuals` observed columns with `fct_cliff_prediction_features` `lap_in_stint, age_in_stint, stint_id` on `lap_id`), `qv_stints`, `qv_pit_stops` (`pit_lane_loss_measured_s` is `pit_lane_loss_s` only where `NOT pit_loss_imputed_flag`; compound before and after is a LEAD over stint order, as `pit-strategy/queries.ts` orders them; verify), `qv_driver_race`, `qv_race_laps`, `qv_circuit_history` (counts only), `qv_teammate_corners`, `qv_circuits`, `qv_compounds`. Dimensions, measures, required filters and exclusions are exactly design 2.5.
2. Write each view to `app/public/data/assistant/qv/` (partitioned by `race_year` for lap-grain), add manifest entries with the usual `{name, path, partitioned, partitionKey, partitions}` shape so `getTablePath` and `registerParquet` work unchanged.
3. Emit `app/public/data/assistant/catalogue.json` (`views`, `ops`, `aggregates`, `limits`, and `catalogue_version = sha256` of its canonical bytes). Add `app/src/assistant/catalogue/catalogue.ts` with the TypeScript type and a loader. `catalogue_version` is copied into the manifest by AX-08.
4. Contract and deny-list checks live in `scripts/tests/test_assistant_query_views.py` (the test home TX-12 creates; run with `./.venv/bin/python -m pytest scripts/tests -q`) and run against a scratch export. Nothing in the Makefile runs it yet; say so in the run note.

## Acceptance

- Every column of every `qv_*` parquet is documented in `catalogue.json` and vice versa (test compares parquet schema to catalogue).
- Deny-list test: no column name matches `_component_s$`, `residual`, `^rating`, `predicted`, `dirty_air`, `hazard`, `tyre_management_score`, `cliff_lap_in_stint`, `cumulative_dirty_air_tax_s`, `teammate_gap_s`.
- Each partition file is under 5 MB (`MAX_FILE_BYTES`); the export prints the sizes.
- Running the export twice on an unchanged warehouse gives identical `qv` file hashes and a clean `--check` (`make app-data-check` logic).
- `qv_driver_race` is either present with `mart_race_driver_summary` exported, or absent from `catalogue.json` with a recorded reason.

## Tests to add

Schema-vs-catalogue, deny-list (with a planted `*_component_s` column proving it fails), size gate, determinism (two runs), `required_filters` present for every lap-grain view, and a TypeScript test that `catalogue.json` parses against the `Catalogue` type.

## Definition of done

All tests above pass on a scratch export (scratch `dev.duckdb` copy, own folder, never the live warehouse); no file under `app/public/data/` is changed except by a deliberate `make app-data` the owner asked for; the view list, sizes and the AX-05 tightening of the deny-list are in the run note. Do not commit.
