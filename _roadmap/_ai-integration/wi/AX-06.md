## Decided (AD2, AD3, design P3, P4)

- The model never writes SQL. It sends one fixed JSON request; the browser validates every field against the catalogue and compiles the SQL from catalogue identifiers only. Values are bound as prepared parameters.
- Request: `{view, filters[{col,op,val}], group_by[<=2 dimension columns], aggregate{fn,col}, order, limit<=25}`. Ops: `eq ne lt lte gt gte in between`; at most 6 filters; `in` at most 20 values. `fn` in `count avg median min max sum` (`sum` only on count-like measures). `order` is the fixed enum `value_asc | value_desc | group_asc`.
- Result: `{view, filters_applied, grain, rows[{..., n}], row_count, rows_shown<=25, rows_dropped, label:"computed_not_card", notes[], result_id}`; values rounded to 3 decimals; a row with `n < 5` carries `thin:true`; no data returns `{status:"no_data", reason}`; a validation error lists the allowed columns and operators for that view.
- Limits: 3 s timeout, 25 rows, read-only, a dedicated connection.

## What the existing code does (read, not run), and why the builder must not reuse it

1. `runLabQuery` calls `result.toArray()` on the whole result and only then slices to `MAX_ROWS = 5000` (`queryLab.ts:126-129`). Nothing bounds work or memory before the cap.
2. It has no timeout: there is no timer or cancel anywhere in `queryLab.ts`.
3. `assertReadOnly` allows any statement that starts with `SELECT`/`WITH`/`FROM` and has none of the words in `FORBIDDEN` (lines 30-31). `read_parquet`, `read_csv` and `http` table functions are not in that list, so `SELECT * FROM read_parquet('https://...')` passes the guard.
4. `registerPartitionedParquet` registers **every** season as one `UNION ALL` view (`register.ts:57-90`), for the 8 seasons in the manifest (the log note's 28.6M telemetry rows were not re-counted).
5. `registerParquet` is idempotent by name and `registerPartitionedParquet`/`registerParquet` share the `registered` Set (`register.ts:7`), so the builder registers per-season aliases (`qv_laps_2024`) exactly as `race-lost/queries.ts:30-36` does.
6. A dedicated connection is a few lines: `getConnection()` then `getDb().connect()` (`queryLab.ts:83-90`, `client.ts:103`). Views registered on the shared connection are visible to it, which is how Query Lab already works.
7. `cancelSent()` exists in the typings. Whether the connection is usable afterwards is NOT tested: close and reopen it after a cancel.

## Method (all under `app/src/assistant/queryBuilder/`)

1. `types.ts`: `QueryRequest`, `QueryResult`, `QueryError {status:'error', code, field, message, allowed?}`. Codes: `unknown_view, unknown_column, bad_op, bad_value, missing_required_filter, too_many_filters, too_many_seasons, bad_group_by, bad_aggregate, bad_limit, bad_order, timeout`.
2. `validate.ts`: `validate(req, catalogue)` returns a branded `ValidatedRequest` or a `QueryError`. Rejects anything not an own property of the request shape (including `__proto__`), non-finite numbers, strings longer than 64 characters, and `season` filters naming more than 2 seasons or any season not in the catalogue. Enforces each view's `required_filters` (for example `qv_laps`: `season`; grouping by `lap_number` needs `race_id`).
3. `compile.ts`: `compile(v: ValidatedRequest)` returns `{sql, params, seasons}`. Identifiers are taken only from catalogue objects, never from request strings. Shape: `SELECT <group cols>, <fn>(<col>) AS value, COUNT(*) AS n, COUNT(*) OVER () AS total_groups FROM <view or per-season alias> WHERE ... GROUP BY ... ORDER BY <enum>, <group cols> LIMIT <limit>`. Using the window count gives an exact `rows_dropped`; the design's `LIMIT n+1` only says "at least one more". Record this departure. Multi-season requests use `UNION ALL` of at most 2 aliases.
4. `run.ts`: registers only the needed `(view, season)` aliases through `registerParquet`, opens its own connection, prepares the statement (`conn.prepare`, `stmt.query(...params)`, `stmt.close()`, as `client.ts:93-95`), races it against a 3 s timer, calls `cancelSent()` on timeout, recreates the connection, then shapes the result (BigInt to number, 3 decimals, `thin`, `result_id`). `result_id` is the first 12 hex of sha256 over the canonical request plus `manifest.version`. Results go into a session store (for the AX-14 render-time grounding check).
5. Never import `runLabQuery`, `assertReadOnly` or `registerPartitionedParquet`. This clears watch AXW5.
6. Make the engine injectable (`Engine {registerPartition, prepareRun, cancel}`) so unit tests run without wasm; the real engine is the code above.

## Acceptance

- A code-path test shows no SQL string comes from model input: `compile()` accepts only a `ValidatedRequest`, the generated SQL for 500 random valid requests contains no request-supplied string (a planted value such as `'; DROP TABLE x; --` appears only in `params`), and the module has no import of the three forbidden functions (static scan of the source).
- 500-case fuzz (seeded generator over bad views, columns, ops, types, limits, prototype keys, oversized arrays): every result is a structured `QueryError` or a valid result shape; none throws.
- Only the filtered seasons are registered: a test with a spy engine asserts the alias set equals the requested seasons.
- Timeout: a never-resolving fake query yields `code:'timeout'` within 3 s and the connection is recreated. Also run the real engine once in Playwright with a deliberately slow query to confirm `cancelSent()` leaves a usable connection (a dev-only `window` hook guarded by `import.meta.env.DEV`; it must not appear in the production bundle).
- Every returned row has `n`; `label` is `computed_not_card`; `rows_shown <= 25`.
