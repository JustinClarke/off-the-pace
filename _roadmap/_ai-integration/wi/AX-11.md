## Decided

- Seven tools stay seven (AD2). Both tools here are fixed JSON shapes; the model never writes chart code, SQL or a URL.
- Chart data is observed lap data from `qv_laps` only (green racing laps, outliers excluded unless asked). Every chart is labelled `computed_not_card` and shows n (AD3, HD4-A).
- Colours come from `app/src/ui/tokens.ts` / the dataviz placeholder palette; no hard-coded hex in new files.

## Method

1. **Chart store** `app/src/assistant/charts/chartStore.ts`: session-scoped map `chart_id -> {spec, rows, n}` and `result_id -> rows`. `query_data` (AX-06) must save the rows it returned under its `result_id`; if AX-06 did not, add that one write there and note it. Rows never leave the store except to the renderer.
2. **`make_chart(spec)`** `charts/makeChart.ts`. Spec: `{type: "line"|"bar"|"scatter", title, x:{col,label}, y:{col,label}, series:[{result_id, label, x_col, y_col}]}`. Validate: at most 6 series; at most 500 points per series; every `result_id` exists in this session; `x_col`/`y_col` exist in that result; title and labels are plain strings of at most 80 chars, rendered as text, never as HTML. Reject with `{status:"error", reason}` (reason names the limit hit). Return to the model only `{chart_id, n, series_count}`.
3. **`compare_lap_times(a, b, race_id)`** `charts/compareLapTimes.ts`: builds the fixed `qv_laps` request (filters `season`, `race_id`, `driver_id in [a,b]`; group by `driver_id` and `lap_number`; aggregate `lap_time_s`), series of at most 80 points each. Driver and race codes must be exact codes (validated against `assistant_entities`, AX-02); a non-code returns an error telling the model to call `list_values`. The model gets back only `{chart_id, n_a, n_b, laps_missing}` where `laps_missing` counts laps present for one driver and not the other (stops, outliers). `query_data` caps at 25 rows for the model; this tool needs up to 160. Do it with an internal-only `rowCap` argument on AX-06's compile function that no tool schema exposes, and add a test that a model-supplied `rowCap` is rejected.
4. **Renderer** `charts/ChartCard.tsx`: map spec type to the existing components in `ui/charts/` (check `Scatter`, `LineWithCIRibbon` props first). If none draws a plain two-series line, add a small wrapper in `app/src/assistant/charts/` and do not edit the shared chart files. The card shows title, axis labels, n per series, the `computed_not_card` label, and a text alternative (a visually hidden table of the plotted points) for screen readers. Wrap in `DataBoundary`/`ErrorBoundary`.
5. Register both tools in AX-10's dispatcher, replacing its stubs; schemas come from the generated catalogue (AX-08), not hand-written.

## Acceptance

- A spec with 7 series or 501 points in a series is rejected with the limit named; 6 series and 500 points is accepted.
- `compare_lap_times("LEC","SAI","2024_8")` (use a real pair from the published data) renders both series with n_a, n_b shown and returns the 4-field result only.
- Headless check: serialise the whole model-facing context of a comparison run and assert no lap row, no array of more than 10 numbers and no `rows` key is present.
- A `result_id` from another session or a made-up one is rejected.
- An HTML string in `title` renders as text (test with `<img onerror>`).
- 3 sample questions (a two-driver comparison, a team-mates comparison, a custom chart from a `query_data` result) produce charts in the CLI and the resulting specs are saved to `_roadmap/_ai-integration/_evidence/ax-11/`.
