## Method

1. **Generated tools (consume only).** AX-08 owns `worker/scripts/gen-tools.mjs`, `worker/src/generated/tools.ts` and the `config.ts` re-export. This item reads `CATALOGUE_VERSION` from it for step 6 and adds nothing to the generator; if it is missing, stop and report.
2. **Question ticket** `worker/src/ticket.ts`. Round 1 of a question needs Turnstile and a visitor slot; the response returns `ticket` (HMAC-SHA256 with new secret `TICKET_SECRET`, payload `{v: visitor hash, q: question id, exp: now+120 s}`). Rounds 2-5 send `X-Question-Ticket` instead of a Turnstile token. A stateless ticket cannot stop replay, so the ledger also counts rounds per `q`: add `takeRound(day, q, max)` to the `Ledger` interface (`ledger.ts:10-17`), the Durable Object (`:65-69` pattern) and `MemoryLedger`. `MAX_ROUNDS = 5` (4 tool calls plus the final answer); round 6 returns 429 `{error:"round_limit"}`. A ticket for another visitor hash, past `exp`, or with a bad MAC returns 403 `abuse_check_failed`.
3. **Per-question limit.** The visitor slot (`handler.ts:144`) is taken only when a ticket is issued. Default `VISITOR_DAILY_LIMIT` becomes 3 (`handler.ts:143` and `wrangler.jsonc`), per HD6. Split the ledger counters: `rounds` (what `answers` counts today) and `questions`; `/admin/usage` (`handler.ts:89`) returns both so AX-13 can compute neurons per answer.
4. **Cap.** Default `DAILY_NEURON_CAP` 90,909 -> 10,000 in `handler.ts:113` and `wrangler.jsonc`. The cap check stays before any token is spent (`:114`); a question already in flight when the cap is hit gets 503 `paused` on its next round.
5. **Output cap.** `MAX_OUTPUT_TOKENS` 800 -> 2,500 provisional (design 2.6), with a comment that AX-13's measurement sets the final value. Do not raise it further without a measurement.
6. **Version skew.** The browser sends `X-Catalogue-Version`. Check it before Turnstile and before any slot; a missing or different value returns 409 `{error:"app_updated"}`. Add `X-Catalogue-Version` and `X-Question-Ticket` to `Access-Control-Allow-Headers` (`handler.ts:40`).
7. **Tool-message size.** In `parseMessages` (`handler.ts:70`) cap `role:"tool"` content at `MAX_TOOL_MESSAGE_CHARS = 5000` (new constant in `config.ts`) and other roles stay at `MAX_MESSAGE_CHARS` 8000.
8. **CSP (`firebase.json:17`)**, HD11 is yes: add the Worker host and `https://challenges.cloudflare.com` to `connect-src`; add it to `script-src`; add `frame-src https://challenges.cloudflare.com`. Keep the header Report-Only (enforcing it is a separate owner decision). The Worker host is known only after the preview deploy: use a clearly marked placeholder and ask the owner for the real value.
9. **CI.** In `worker-ci.yml` add steps that build the app (`app/` install and `build`, which writes `app/dist`) then run `npm run scan-bundle` (`worker/package.json`), plus a negative step proving a planted key in a temp dir makes the scan exit 1.
10. Re-confirm gpt-oss-20b tool-call support from the Cloudflare model page and record the source and date in this doc's history note (watch AXW7).

## Acceptance

- All 16 existing tests still pass (those that encode the old limits are updated, not deleted, and listed in the final report).
- A 5-round question spends exactly 1 Turnstile call (`fetchMock` called once) and 1 visitor slot; round 6 is refused.
- A replayed, expired, forged or other-visitor ticket is refused; a fourth question in a day from one visitor is refused at the default limit of 3.
- A catalogue-version mismatch (or missing header) returns 409 and spends no Turnstile token or slot.
- Default cap is 10,000 and a question in flight at the cap gets `paused`.
- A tool message over 5,000 chars is a 400.
- `scan-bundle` runs in CI and fails on a planted key.
- Preview deploy (owner) answers one real 3-round question; the usage readout shows 1 question and 3 rounds.
