## The problem (re-verified 2026-11-07 on the audit's scratch build, 3,138 rows, 171 races)

- `rating_s` is `driver_skill_loro_s`: the **median of paired lap-time gaps** to the teammate (`int_driver_race_skill_loro.sql` header lines 5-12; `paired_agg` lines 196-207).
- The interval is `rating_s ± 1.96 × STDDEV(driver_skill_residual_s) / SQRT(n)` (`mart_race_driver_summary.sql:29-30, 105-106`): the SE of a *mean* of a *field-relative residual* over a *different lap set* (all `ml_eligible` laps). It brackets a number it was not computed from.
- `paired_lap_count` exists upstream (`int_driver_race_skill_loro.sql:204, 244, 297`) and the mart drops it.

## Method

1. **Extract the paired laps.** Move the `clean_panel` → `paired_laps` CTEs of `int_driver_race_skill_loro.sql` into a new model `transform/models/intermediate/int_driver_race_paired_laps.sql` (grain: race × driver × lap_number × teammate; columns `race_year, race_id, constructor_id, driver_id, lap_number, paired_delta_s`). `int_driver_race_skill_loro` then reads it. **Its output must stay byte-identical** (it feeds the whole rating chain and is exported to the app as an intermediate). Do not add columns to it.
2. **Distribution-free CI for the median** (deterministic, so the byte oracle stays stable; no bootstrap). For n paired deltas sorted x₁ ≤ … ≤ xₙ, let j = the largest k with P(Bin(n, ½) ≤ k − 1) ≤ 0.025. CI = [x_j, x_{n−j+1}], coverage ≥ 95%. No such j exists for n < 6, so the CI is NULL there. Compute j in SQL (`lgamma` over `range()`, compare with a 1e-12 tolerance) or a tiny macro. Known values for a test: n = 6 → j = 1; n = 10 → j = 2; n = 20 → j = 6. For a two-driver car the teammate's CI is the exact mirror.
   Prototype result on the scratch build: 3,000 of 3,138 rows get a CI, 138 are NULL (n < 6); every CI contains `rating_s`; median width 0.49 s vs 0.434 s today, wider on 1,753 of 2,916 rows that have both. 2024_1 VER: [−0.755, −0.390] (today [−0.892, −0.352]). 2020_14 HAM / 2018_13 VET: NULL (1 paired lap).
3. **Mart** (`mart_race_driver_summary.sql`): replace `ci_low/ci_high` with the step-2 bounds (drop `lap_se_s` from the CI); add `paired_lap_count` and `rating_trust_label`: `suppressed` when n < 6, `thin` when 6 ≤ n < 12, `ok` otherwise (scratch counts 138 / 70 / 2,930 at the first cut of 10; ruled 12 on 2026-11-08: 138 / 94 / 2,906, because at n=5 the best exact interval covers only 93.75%). Keep `n_clean_laps` and its meaning. Rewrite the header comment (lines 10-13).
4. `schema.yml`: model description and `ci_low`, `ci_high`, `paired_lap_count`, `rating_trust_label` descriptions saying exactly the step-2 statistic. Docs pages under `docs/reference/models/` are generated; regenerate them only if that is the house step (see `scripts/gen_dbt_reference.py`), do not hand-edit.

**Must not move:** label version v16 and `transform/seeds/label_stability_baseline.csv`; `rating_s`, `teammate_gap_s`, every other column of this mart; every other mart; `int_driver_race_skill_loro` (byte-identical); every `fct_*` hash in your own `$S/before.json`.
