## The problem (re-verified 2026-11-07, scratch warehouse)

- The fit file has 8,074 rows: `fit_date 2026-09-24`, `git_sha 57c4039`, `data_window 2018_to_2025`. The envelope has **8,115** cells.
- **44 cells have no fit row**, so `*_mono_s` is NULL there (reproduces). The largest groups are Jeddah pre2022 HARD and `_all` (17 rows) and Albert Park post2022 HARD and `_all` laps 45-50 (12 rows).
- Mean |mono − raw p50| = 0.339 s, p95 1.35 s (reproduces).
- **709 cells have `n_observations < 5`** (1,985 below 10). The minimum is 3, from the filter at line 161 (reproduces).
- The line 38 comment says post2022 = 2022-2024; 2025 is included (reproduces).
- **"Hardcoded fallbacks fill 2,261 rows" does NOT reproduce as stated.** The `COALESCE(..., 1.0 / 8.0 / 0.010)` at lines 151-153 fires on exactly **44** rows: the cells with no fit row. The 2,261 rows with `temp_headroom_c = 8.0` are 2,234 `_all`-compound rows plus 27 others. Of the `_all` rows, 2,217 carry 8.0 because the fit itself writes it: `COMPOUND_HEADROOM_C["_all"] = 8.0`, fit script line 111. `temp_penalty_s_per_deg = 0.010` is on all 8,115 rows because it is the fit's single constant `TEMP_PENALTY` (line 116). A refit removes the 44 fallback rows. It does not change the 8.0 or 0.010 design constants.
- The fit script hard-codes `DB_PATH = data/dev.duckdb` and `OUT_PATH = data/fits/...` (lines 71-72). It reads `mart_degradation_history_envelope` (line 125) and `int_lap_residual_decomposed` (line 140), so the order is: build, fit, rebuild the envelope.

## Method

1. Add `--db` and `--out` arguments to `fit_degradation_isotonic.py`, defaulting to today's paths so `make deg-iso-fit` is unchanged. No other change to the fit logic or constants.
2. Fix the era comment at envelope line 38 (comment only).
3. Refit in scratch:

**Threads and oracle (the same in every TX doc):** every dbt run uses 1 thread (`threads: 1` plus `settings: {threads: 1}`). The byte oracle is your own before-snapshot `$S/before.json`, taken on your copy after rebuilding the selection unchanged, never the committed `transform/tests/model_hashes*.baseline.json`: a 4-thread scratch build already drifts from it on 11 `fct_*` models (TX-07, checked 2026-11-07). Never edit those baseline files (TX-07's `dim_events` key removal is the one exception); the owner re-takes them once, after TX-01..07 land. Copy from `<your scratchpad>/base/dev.duckdb` when the shared base build exists (one full build of the current tree at 1 thread); otherwise from `data/dev.duckdb` (copy only), which predates the v16 seal, so the unchanged rebuild before the snapshot matters.

```bash
S=<your scratchpad>/tx-09; mkdir -p "$S/fits"             # own folder; never share a profiles.yml
B=<your scratchpad>/base/dev.duckdb; [ -f "$B" ] || B=/Users/justin/github/off-the-pace/data/dev.duckdb
cp "$B" "$S/dev.duckdb"                                    # name MUST stay dev.duckdb
cp /Users/justin/github/off-the-pace/data/fits/*.parquet "$S/fits/"   # every fit, so fits_base can point here
printf "off_the_pace:\n  target: dev\n  outputs:\n    dev:\n      type: duckdb\n      path: '%s/dev.duckdb'\n      threads: 1\n      settings: {threads: 1, memory_limit: '4GB'}\n" "$S" > "$S/profiles.yml"
cd /Users/justin/github/off-the-pace/transform
D="--profiles-dir $S --target-path $S/target --log-path $S/logs"; V="{\"fits_base\": \"$S/fits\"}"
../.venv/bin/dbt build $D --vars "$V"                      # before the refit: unchanged
../.venv/bin/python scripts/snapshot_model_hashes.py --db "$S/dev.duckdb" --manifest "$S/target/manifest.json" --baseline "$S/before.json"
../.venv/bin/python -c "import duckdb;duckdb.connect('$S/dev.duckdb',read_only=True).execute(\"COPY mart_degradation_history_envelope TO '$S/envelope_before.parquet'\")"
../.venv/bin/python -m tasks.coefficients.fit_degradation_isotonic --db "$S/dev.duckdb" --out "$S/fits/degradation_isotonic.parquet"
../.venv/bin/dbt build $D --vars "$V" -s mart_degradation_history_envelope+
../.venv/bin/python scripts/snapshot_model_hashes.py --check --db "$S/dev.duckdb" --manifest "$S/target/manifest.json" --baseline "$S/before.json"
```

4. Write the diff for the owner: rows per column changed, mean and p95 |Δ| for each `*_mono_s` column and each multiplier, the count of rows still unmatched (target 0), and the 10 largest moves with circuit, era, compound and lap.

**Must not move:** only `mart_degradation_history_envelope` and its downstream may change in the `--check` (list every model that drifts; anything upstream is a defect). Label version stays v16.
