## Method

1. **Flags.** Use TX-12's `--db` / `--out`; add none. `make app-data` must behave exactly as now.
2. **Tables.** Add `mart_race_driver_summary`, `mart_driver_season_summary` and `mart_metric_benchmark` (subdir `marts`, unpartitioned: all are well under the 5 MB gate) and `fct_driver_isolation_race` (subdir `facts`). Export them with the TX-01..TX-06 columns as landed. Do not add marts the audit marked "do not quote" (training frames, pair-lap grain).
3. **Freshness.** Give each manifest entry `rows` and a content hash. Reuse the `md5_number` / `bit_xor` method in `transform/scripts/snapshot_model_hashes.py` so it matches the byte oracle. Make `--check` compare these against the warehouse and exit 1 on any difference. Copy the TX-05 provenance (label version, build id) into the manifest top level.
4. **Dry run on scratch, never on the real paths.** **Threads and oracle (the same in every TX doc):** every dbt run uses 1 thread (`threads: 1` plus `settings: {threads: 1}`). The byte oracle is your own before-snapshot `$S/before.json`, taken on your copy after rebuilding the selection unchanged, never the committed `transform/tests/model_hashes*.baseline.json`: a 4-thread scratch build already drifts from it on 11 `fct_*` models (TX-07, checked 2026-11-07). Never edit those baseline files (TX-07's `dim_events` key removal is the one exception); the owner re-takes them once, after TX-01..07 land. Copy from `<your scratchpad>/base/dev.duckdb` when the shared base build exists (one full build of the current tree at 1 thread); otherwise from `data/dev.duckdb` (copy only), which predates the v16 seal, so the unchanged rebuild before the snapshot matters.

```bash
S=<your scratchpad>/tx-11 ; mkdir -p $S/out ; cp data/dev.duckdb $S/dev.duckdb   # name must stay dev.duckdb
# (if TX-01..07 are not yet in data/dev.duckdb, rebuild them in $S first: own profiles.yml with threads: 1 and settings: {threads: 1}, ../.venv/bin/dbt build --profiles-dir $S --target-path $S/target --log-path $S/logs, run from transform/)
.venv/bin/python scripts/export_app_data.py --db $S/dev.duckdb --out $S/out
.venv/bin/python scripts/export_app_data.py --db $S/dev.duckdb --out $S/out --check     # passes
# then change one row in a scratch table and confirm --check fails
```

5. Write a comparison of `$S/out/_manifest.json` against the tracked manifest: tables added or removed, stats that change, rows per table.

**Must not move:** the ML files the export copies (`data/marts/mart_degradation_predictions.parquet`, `driver_network_rating.parquet`) are parked under PK1 and must be byte-identical in the output. Existing table paths and names stay as they are (the app's `getTablePath` reads them). `app/src/data/manifest.ts` types gain optional fields only.
