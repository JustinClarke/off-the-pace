## The problem (read 2026-11-07)

- Warehouse and output are constants. `run_export` exits when `DB_PATH` is missing (:590) and writes to `APP_DATA` (:600). `--check` exports to a temp dir, then compares with `APP_DATA / "_manifest.json"` (:696). So no scratch export, no headless card run (AX-04) and no `--check` against a scratch build is possible without editing the constants.
- Four docs planned to add the same flags (TX-05 step 4, TX-11 step 1, AX-02, AX-04 finding 1). This item does it once.
- **Paths that do not follow `--db`, left as they are:** the ML parquet files `MART_PREDS` and `DRIVER_NETWORK_RATING` (`data/marts/`, parked under PK1), `ml/model_card.json` (TX-07 fixes that read) and the dbt manifest behind `stats.dbt_models` (`transform/target/manifest.json`). A scratch dbt build with `--target-path $S/target` therefore reports the repo's model count, not the scratch count. Say so in the run note. Do not change it here.
- **Test home.** `scripts/` has no test folder. AP-04 and TX-11 planned `scripts/tests/`, and AX-05 planned `scripts/test_*.py`. Decided: `scripts/tests/`, created by this item.

## Method

1. Move the parser into `build_parser()` so tests can call it. Add `--db PATH` (default `DB_PATH`) and `--out DIR` (default `APP_DATA`). Pass both into `run_export(..., db_path=..., out_root=...)`. `_run_export_to` connects to `db_path`. Do not reassign the module constants.
2. `--check` with `--out` compares against `<out>/_manifest.json`. Without `--out` it compares against `APP_DATA/_manifest.json`, as today. The temp-dir export itself is unchanged.
3. **Guard.** If `--db` is not the default, the resolved output is `APP_DATA` and `--check` is not set, exit 2 with "refusing to write a scratch warehouse into app/public/data; pass --out". A scratch export can then never overwrite tracked files. With no flags, nothing changes.
4. Keep every print line's format; the `warehouse:` and `output:` lines already print the paths.
5. Add the two flags to the module docstring's Usage block. No Makefile change: `make app-data` and `make app-data-check` pass no flags.
6. Create `scripts/tests/` with `conftest.py` (puts `scripts/` on `sys.path`) and `test_export_app_data.py`. Later items (TX-07 part B, TX-11, AX-05, AX-08, AX-19) add their tests here.

**Must not move:** default behaviour. With no flags, the same warehouse is read, the same files are written under `app/public/data/`, and `--check` compares against the same manifest. No `TABLES` entry, stats key or manifest field changes. Do not run `make app-data`: it rewrites tracked files (HD12).

## How to run (own scratch copy; never write `data/dev.duckdb` or `data/ci.duckdb`)

This item runs no dbt. The TX rule still holds if you build anything: every dbt run uses 1 thread (`threads: 1` plus `settings: {threads: 1}`) and is compared to your own before-snapshot `$S/before.json`, never to the committed `model_hashes*.baseline.json`.

```bash
S=<your scratchpad>/tx-12; mkdir -p "$S"
B=<your scratchpad>/base/dev.duckdb; [ -f "$B" ] || B=/Users/justin/github/off-the-pace/data/dev.duckdb
cp "$B" "$S/dev.duckdb"                                  # name must stay dev.duckdb
cd /Users/justin/github/off-the-pace
# before editing: default behaviour (opens data/dev.duckdb read-only, writes only a temp dir)
./.venv/bin/python scripts/export_app_data.py --check > "$S/check_before.txt" 2>&1; echo "exit $?" >> "$S/check_before.txt"
# ...edit...
./.venv/bin/python scripts/export_app_data.py --check > "$S/check_after.txt" 2>&1; echo "exit $?" >> "$S/check_after.txt"
./.venv/bin/python scripts/export_app_data.py --db "$S/dev.duckdb" --out "$S/out"
./.venv/bin/python scripts/export_app_data.py --db "$S/dev.duckdb" --out "$S/out" --check   # must pass
./.venv/bin/python -m pytest scripts/tests -q            # venv python; plain python3 is 3.9
git status --short app/public/data                       # must print nothing
```

## Acceptance

- `check_before.txt` and `check_after.txt` are identical once the temp-dir name is masked, including the exit code. Today the exit code may be 1, because the served manifest is stale (TX-11). What matters is that it is the same before and after.
- A full scratch export to `$S/out` followed by `--check --db --out` on the same scratch copy prints "No drift" and exits 0.
- The guard: `--db $S/dev.duckdb` with no `--out` and no `--check` exits 2 and writes nothing.
- `git status --short app/public/data` is empty. `python -m py_compile scripts/export_app_data.py` passes.

## Tests to add (`scripts/tests/test_export_app_data.py`)

- **Defaults.** `build_parser().parse_args([])` gives `db == DB_PATH` and `out == APP_DATA`. A `run_export` spy (monkeypatch) receives exactly those paths.
- **Scratch round trip.** Build a tiny DuckDB file in `tmp_path` with the tables `build_stats_block` reads (`fct_lap_residuals(race_year)`, `dim_drivers`, `dim_events`, `race_to_track(track_id)`). Run the script in a subprocess (`sys.executable`) with `--db tiny --out tmp/out --table race_to_track`. Then run `--check` with the same flags: it exits 0. Insert one `fct_lap_residuals` row, which changes `stats.total_laps`: `--check` now exits 1. This also shows the manifest-only gate that TX-11 strengthens.
- **Guard.** `--db tiny` alone exits 2, and `app/public/data/_manifest.json`'s mtime is unchanged.
- When TX-07 removes `total_events`, it drops `dim_events` from this fixture.
