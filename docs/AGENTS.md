# Documentation project instructions

## About this project

- This is the documentation site for **Off The Pace**, an F1 causal lap-time decomposition and performance-analysis project. It is built on [Mintlify](https://mintlify.com).
- Pages are MDX files with YAML frontmatter. Navigation and configuration live in `docs.json`.
- The site has five tabs, one per pipeline layer plus an Overview: **Overview** (recruiter-facing, what the system does), **Data** (sources, Bronze schemas, ingestion how-to), **Transform** (the model DAG by family, the CI test suite, and macros), **Machine Learning** (Concepts, Pipeline, Validation & Trust, CI Contract, Model Reference five groups covering the 42-feature contract, the leakage spine, quantile calibration, ONNX parity, and 28 CI tests), and **App** (React feature pages). Each layer tab folds in its own generated reference schemas, dbt models/macros, ML models there's no separate Reference tab.

## Terminology

- **Feature** a `app/src/features/<dir>/` module that renders through the shared `FeaturePage` template. The directory name is the feature's canonical **slug**.
- **Page** a feature's public docs page at `docs/app/<slug>.mdx`. Slug equals the feature directory name, exactly.
- **Pillar** a top-level navigation grouping in the app (`app/src/nav/pillars.ts`): Ghost Car, Lap Decomposition, Tyre & Strategy, Aero & Conditions, Drivers, Constructors, The Machine, Query Lab, Data Quality.
- **Mart / model** a dbt model in the warehouse. Its column-level docs live under `docs/reference/models/<sub>/` and are **autogenerated** never hand-edit `docs/reference/**`.
- Use "decomposition", "residual", "structural pace", and "cliff" with their project meanings (see the **Transform** tab's Concepts group and the **Machine Learning** tab); don't invent synonyms.

## Style preferences

- Use active voice and second person ("you").
- Keep sentences concise one idea per sentence.
- Use sentence case for headings.
- Bold for UI elements: Click **Settings**.
- Code formatting for file names, commands, paths, column names, and model names.
- Sign convention is consistent across the app: **negative = faster** (green), **positive = slower** (red). State it on any page that shows a residual.

## App feature-page contract

Every `docs/app/<slug>.mdx` page (except the hand-written `query-lab.mdx`) is built from `docs/snippets/app-page-template.mdx` and must carry, in order:

1. **Frontmatter** `title` (the question the feature answers, sentence case), `sidebarTitle` (short nav label), `description`.
2. **Hook** one opening paragraph naming the core metric and its sign convention.
3. **What it shows** each axis / series / cell mapped to a concrete column name.
4. **How to use it / Reading the signal** interaction steps and an interpretation caveat in a `<Note>` / `<Warning>`.
5. **Data source** the DuckDB-Wasm query target, a column→meaning table, the data window, and a link to the underlying dbt-model reference page.

The page's slug must match the feature directory, be registered in the `docs.json` "App & Visualizations" group, and the feature's `methodologyHref` must equal `` `${CANONICAL_DOCS_BASE}/app/<slug>` ``. The `scripts/app_docs_audit.py` gate enforces all of this.

## Content boundaries

- **Document every shipped feature.** A feature is shipped when its `routes.ts` entry has a `featureId` and is not `shipped: false`. There are 30 such features plus Query Lab.
- **Do not document `shipped: false` routes** the 16 roadmap stubs live on `/roadmap`, not in `docs/app/`.
- **Do not hand-edit `docs/reference/**`** it is regenerated from the dbt project by `scripts/build_reference.py` and gated by a drift check.
- Link a feature page to its dbt model's reference page; do not point the in-app "methodology" button at a raw reference page (it must point at the `/app/<slug>` page).
