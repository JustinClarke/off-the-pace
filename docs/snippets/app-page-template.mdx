Open with the **hook**: the single question this feature answers, in plain language, and what a
reader gets from it. One short paragraph. Name the core metric in `code` and its sign convention.

## What it shows

Map each axis / series / cell to a concrete column name from the mart the feature queries.

- **X-axis / first series (`column_name`)**: what it is and what direction means what.
- **Y-axis / second series (`column_name`)**: same.
- **Encoding (colour / size / shading)**: what it encodes and the sign convention
  (negative = faster/green, positive = slower/red, mirroring the residual convention).

<Note>
  State the inclusion filter the query applies (clean laps only, `n_obs >= 2`, minimum sample,
  etc.) so a reader knows why some rows are absent.
</Note>

## How to use it

1. **Select a season / driver / race** using the filter bar; the chart reloads automatically.
2. **Hover** to read the per-point detail (name, constructor, the metric, sample size).
3. **Compare** across the relevant dimension to read the signal the feature is built for.
4. **Export the data** with the CSV button in the page header to analyse the raw rows yourself.

## Reading the signal correctly

Explain what the signal does and does **not** mean especially what has already been controlled
for, so the reader does not double-count or over-interpret.

<Warning>
  Call out the caveat that matters most for this feature (survivorship, small samples,
  `REVIEW_REQUIRED` circuits, prior-dominated estimates, etc.) and link the relevant
  [decomposition limitations](/decomposition/limitations) page where appropriate.
</Warning>
